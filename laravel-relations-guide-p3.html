مقدمه – روابط درEloquent

در Laravel، Eloquent ORM روابط بین مدل‌ها را به صورت شی‌گرا مدیریت می‌کند. هر رابطه به عنوان یک متد در مدل تعریف می‌شود و امکان دسترسی آسان به داده‌های مرتبط را فراهم می‌آورد.

نکته کلیدی: متد رابطه همیشه در مدلی تعریف می‌شود که می‌خواهی از آن به مدل دیگر دسترسی پیدا کنی. مثلاً اگر بخواهی از User به Post برسی، رابطه در User تعریف می‌شود.

hasOne & belongsTo – رابطه یک به یک

سناریو: هر کاربر یک پروفایل دارد.

ساختار جدول‌ها

جدول users

id
name
email

جدول profiles

id
user_id (foreign key)
avatar
bio

Foreign Key در جدول profiles قرار می‌گیرد.

Migration

Schema::create('profiles', function (Blueprint $table) {
    $table->id();
    $table->foreignId('user_id')
        ->constrained()
        ->cascadeOnDelete();
    $table->string('avatar')->nullable();
    $table->text('bio')->nullable();
    $table->timestamps();
});

مدل‌ها

User

class User extends Model
{
    public function profile()
    {
        return $this->hasOne(Profile::class);
    }
}

Profile

class Profile extends Model
{
    public function user()
    {
        return $this->belongsTo(User::class);
    }
}

استفاده عملی

$user = User::find(1);
$profile = $user->profile; // دریافت پروفایل

// ایجاد پروفایل جدید
$user->profile()->create([
    'bio' => 'Laravel Developer',
    'avatar' => 'avatar.jpg',
]);
سؤال مصاحبه: چرا hasOne در User و belongsTo در Profile؟
چون Profile جدول وابسته است و Foreign Key را نگه می‌دارد.

hasMany & belongsTo – رابطه یک به چند

سناریو: هر کاربر چند پست دارد.

ساختار جدول‌ها

جدول users

id
name

جدول posts

id
user_id (foreign key)
title
content

مدل‌ها

User

public function posts()
{
    return $this->hasMany(Post::class);
}

Post

public function user()
{
    return $this->belongsTo(User::class);
}

استفاده عملی

$user = User::find(1);
$user->posts; // Collection از تمام پست‌ها

// ایجاد پست جدید
$user->posts()->create([
    'title' => 'Laravel Relations',
    'content' => '...',
]);

// فیلتر کردن با Query Builder
$publishedPosts = $user->posts()->where('status', 'published')->get();

✅ تفاوت $user->posts و $user->posts()

$user->posts یک Collection برمی‌گرداند (داده‌های بارگذاری‌شده).
$user->posts() یک Relation Builder برمی‌گرداند که می‌توان روی آن کوئری نوشت.

belongsToMany – رابطه چند به چند

سناریو: هر کاربر در چند وب‌سایت عضو است و هر وب‌سایت چند کاربر دارد.

ساختار جدول‌ها

جدول users

id
name

جدول websites

id
title

جدول Pivot user_website

user_id (foreign key)
website_id (foreign key)
role (ستون اضافی)
joined_at (ستون اضافی)
primary key: (user_id, website_id)

Migration Pivot

Schema::create('user_website', function (Blueprint $table) {
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->foreignId('website_id')->constrained()->cascadeOnDelete();
    $table->string('role');
    $table->timestamp('joined_at');
    $table->primary(['user_id', 'website_id']);
});

مدل‌ها

User

public function websites()
{
    return $this->belongsToMany(Website::class)
        ->withPivot('role', 'joined_at')
        ->withTimestamps();
}

Website

public function users()
{
    return $this->belongsToMany(User::class)
        ->withPivot('role', 'joined_at');
}

استفاده عملی

$user = User::find(1);
$user->websites; // Collection از وب‌سایت‌ها

// دسترسی به Pivot
foreach ($user->websites as $website) {
    echo $website->pivot->role;
    echo $website->pivot->joined_at;
}

متدهای مهم Pivot

  • attach($id, $attributes) – اضافه کردن رابطه
  • detach($id) – حذف رابطه
  • sync([$ids]) – همگام‌سازی (حذف و اضافه)
  • syncWithoutDetaching([$ids]) – فقط اضافه
  • updateExistingPivot($id, $attributes) – به‌روزرسانی ستون‌های Pivot
سؤال مصاحبه: اگر نام جدول Pivot website_members باشد، چه چیزی باید در belongsToMany تغییر کند؟ 
return $this->belongsToMany(Website::class, 'website_members');
آرگومان دوم نام جدول Pivot است.

hasManyThrough – رابطه غیرمستقیم

سناریو: هر کشور چند کاربر دارد و هر کاربر چند پست. می‌خواهیم از Country به Post برسیم.

ساختار جدول‌ها

countries

id
name

users

id
country_id

posts

id
user_id

مدل Country

class Country extends Model
{
    public function posts()
    {
        return $this->hasManyThrough(
            Post::class,
            User::class
        );
    }
}

استفاده عملی

$country = Country::find(1);
$country->posts; // تمام پست‌های کاربران آن کشور

Laravel کوئری زیر را اجرا می‌کند:

SELECT posts.*
FROM posts
JOIN users ON users.id = posts.user_id
WHERE users.country_id = 1;

✅ چه زمانی از hasManyThrough استفاده می‌کنیم؟

وقتی می‌خواهیم از طریق یک مدل واسط به مدل نهایی برسیم و نیازی به مدیریت Pivot نداریم. مثال‌های واقعی: Company → Tasks، Organization → Tickets.

تفاوت belongsToMany و hasManyThrough چیست؟
belongsToMany برای رابطه چند به چند با جدول Pivot است.
hasManyThrough برای رابطه یک به چند غیرمستقیم (از طریق یک مدل واسط) استفاده می‌شود.

روابط Polymorphic (چندریختی)

ایده اصلی: یک جدول بتواند با چند مدل مختلف رابطه داشته باشد.
مثال: Comment می‌تواند متعلق به Post، Product یا Video باشد.

morphOne – یک به یک چندریختی

سناریو: هم User و هم Post یک تصویر اصلی دارند.

ساختار جدول images

id
url
imageable_id
imageable_type  // مقدار: 'App\Models\User' یا 'App\Models\Post'
timestamps

Migration

Schema::create('images', function (Blueprint $table) {
    $table->id();
    $table->string('url');
    $table->morphs('imageable'); // imageable_id + imageable_type
    $table->timestamps();
});

مدل‌ها

User

public function image()
{
    return $this->morphOne(Image::class, 'imageable');
}

Post

public function image()
{
    return $this->morphOne(Image::class, 'imageable');
}

Image

public function imageable()
{
    return $this->morphTo();
}

استفاده عملی

$user = User::find(1);
echo $user->image->url;

$post = Post::find(10);
echo $post->image->url;

// ایجاد تصویر برای کاربر
$user->image()->create(['url' => '/avatars/user1.jpg']);
تفاوت morphOne و hasOne چیست؟
hasOne فقط با یک مدل مشخص کار می‌کند (مثلاً User → Profile).
morphOne با چند مدل مختلف می‌تواند ارتباط داشته باشد (مثلاً User → Image و Post → Image).

morphMany – یک به چند چندریختی

سناریو: Post، Product و User همه می‌توانند Comment داشته باشند.

ساختار جدول comments

id
body
commentable_id
commentable_type  // 'App\Models\Post' یا 'App\Models\Product'
timestamps

مدل‌ها

Post

public function comments()
{
    return $this->morphMany(Comment::class, 'commentable');
}

Product

public function comments()
{
    return $this->morphMany(Comment::class, 'commentable');
}

Comment

public function commentable()
{
    return $this->morphTo();
}

استفاده عملی

$post = Post::find(1);
$post->comments; // Collection از کامنت‌ها

$comment = Comment::find(5);
$comment->commentable; // مدل والد (Post یا Product)

// ایجاد کامنت برای پست
$post->comments()->create(['body' => 'Laravel is great!']);
تفاوت morphMany و morphTo چیست؟
morphMany در مدل مالک (مثلاً Post) تعریف می‌شود و نشان می‌دهد که چند مدل وابسته دارد.
morphTo در مدل وابسته (مثلاً Comment) تعریف می‌شود و مشخص می‌کند که به کدام مدل تعلق دارد.

morphToMany – چند به چند چندریختی

سناریو: Post، Video و Product همگی می‌توانند Tag داشته باشند.

ساختار جدول‌ها

tags

id
name

جدول Pivot taggables

tag_id
taggable_id
taggable_type  // 'App\Models\Post' یا 'App\Models\Video'

مدل‌ها

Post

public function tags()
{
    return $this->morphToMany(Tag::class, 'taggable');
}

Video

public function tags()
{
    return $this->morphToMany(Tag::class, 'taggable');
}

Tag

public function posts()
{
    return $this->morphedByMany(Post::class, 'taggable');
}

public function videos()
{
    return $this->morphedByMany(Video::class, 'taggable');
}
تفاوت belongsToMany و morphToMany چیست؟
belongsToMany بین دو مدل مشخص (User ↔ Role) استفاده می‌شود.
morphToMany برای ارتباط یک مدل با چند مدل دیگر (Tag با Post, Video, Product) استفاده می‌شود.

نکات عملکردی و بهینه‌سازی

تفاوت with() و load()

with() – Eager Loading قبل از کوئری

$users = User::with('posts')->get();
// ۲ کوئری: users + posts

load() – Lazy Eager Loading بعد از کوئری

$users = User::all();
$users->load('posts');
// ۲ کوئری: users + posts (اما جدا)
نکته: از with() زمانی استفاده می‌کنیم که از قبل می‌دانیم به رابطه نیاز داریم. از load() زمانی که بعداً تصمیم می‌گیریم رابطه را بارگذاری کنیم.

شمارش و جمع‌آوری

// شمارش پست‌های هر کاربر
$users = User::withCount('posts')->get();
echo $users[0]->posts_count;

// جمع بازدیدها
$posts = Post::withSum('views', 'count')->get();
echo $posts[0]->views_sum_count;

بارگذاری شرطی

$users = User::with(['posts' => function ($query) {
    $query->where('status', 'published');
}])->get();

سؤالات متداول مصاحبه

۱. Foreign Key در هر رابطه کجاست؟
  • hasOne / hasMany → جدول فرزند
  • belongsTo → جدول فعلی (همین مدل)
  • belongsToMany → جدول Pivot
  • hasManyThrough → جدول واسط و جدول نهایی
۲. تفاوت with() و load() چیست؟
with() برای Eager Loading قبل از اجرای کوئری استفاده می‌شود.
load() بعد از دریافت مدل یا Collection استفاده می‌شود (Lazy Eager Loading).
۳. چه زمانی از Polymorphic Relations استفاده می‌کنیم؟
وقتی یک مدل (مثلاً Comment) باید بتواند به چند مدل مختلف (Post, Product, Video) متصل شود.
۴. فرق morphMany و morphTo چیست؟
morphMany در مدل مالک (Post) تعریف می‌شود.
morphTo در مدل وابسته (Comment) تعریف می‌شود.
۵. اگر جدول Pivot نام متفاوتی داشته باشد، چه می‌کنیم؟
آرگومان دوم belongsToMany را تغییر می‌دهیم: 
return $this->belongsToMany(Website::class, 'website_members');
